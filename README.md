# mephi-botcreators-users-bot

Телеграм‑бот для анализа истории чатов по их **экспортам** из Telegram Desktop. Бот помогает собрать информацию об участниках, упоминаниях и активности в группе.

---

## Как работает бот

### Краткий How‑to для пользователя

1. **Подготовить экспорт из Telegram Desktop**
   - Открыть Telegram Desktop.
   - Перейти в `Settings → Advanced → Export Telegram data`  
     или через меню нужного чата `… → Export chat history`.
   - Выбрать нужный чат/группу.
   - Формат: **JSON** (по возможности) или **HTML**; при необходимости можно получить ZIP‑архив.
   - При больших чатах выключить медиа и/или сократить период, чтобы итоговый размер был ≤ 20 МБ.

2. **Отправить экспорт боту**
   - Найти бота в Telegram.
   - Отправить один или несколько файлов экспорта как документы.
   - Следовать подсказкам бота (например:
     - `/reset` — очистить текущее состояние и список файлов,
     - `/process` — запустить обработку, если это предусмотрено логикой бота).

3. **Получить результат**
   - Бот вернёт агрегированную информацию по пользователям/упоминаниям/каналам в соответствии со своей логикой обработки.

#### ⚠️ Важно понимать источник данных:

Бот **не получает список участников напрямую из Telegram** и **не использует Telegram API**
для запроса профилей пользователей.

Все данные извлекаются **исключительно из файлов экспорта**, которые предоставляет сам Telegram Desktop.
Если информация отсутствует в экспорте, бот не может получить её иным способом.

## Какие данные извлекает бот

На основе файлов экспорта бот извлекает:

### 1. Пользователей (Participants)

Пользователи, которые **писали сообщения** в чате;

Если у пользователя есть отображаемое имя — оно будет сохранено как *chat name*.

### 2. Упоминания (Mentions)

Отдельно собирается список всех уникальных `@username`, найденных в тексте сообщений.

### 3. Каналы (Channels)

Бот извлекает каналы, упомянутые в сообщениях в формате ссылок `t.me/channel_name`.

Без обращения к Telegram API невозможно на 100% отличить пользователя от канала, поэтому все @ находятся 
во вкладке упоминания, список каналов формируется **на основе формата ссылки t.me**.

## Структура Excel-файла

Excel-файл содержит несколько вкладок.


### 1. Mentions

Список всех уникальных `@username`, найденных в тексте сообщений.

Колонки:
- **Дата экспорта**
- **Username**

### 2. Display Names

Общий список участников чата.

Колонки:
- **Дата экспорта** — дата генерации файла;
- **Имя и фамилия** — отображаемое имя автора сообщения;

### 3. Channels

Список каналов, упомянутых в сообщениях.

Колонки:
- **Дата экспорта**
- **Channel**

## Ограничения Telegram по файлам

### Лимиты Bot API

При использовании обычного Bot API (облако Telegram):

- Бот может **получать/отправлять файлы до ~50 МБ**.
- Но через `getFile` бот может **скачивать файл только если его размер ≤ ~20 МБ**.

Для нашего сценария важен именно второй пункт:  
если экспорт чата больше ~20 МБ, бот **не сможет его скачать и обработать**, даже если он дошёл как документ.

### Как подстроиться под эти ограничения

- Рекомендуется:
  - при экспорте **отключать медиа** (фото/видео/файлы) и/или сокращать период истории;
  - следить, чтобы итоговый размер файла экспорта был **≤ 20 МБ**.
- В коде бот проверяет `document.file_size` и может отвечать пользователю, если файл слишком большой:
  - сообщение вида:  
    «Telegram Bot API не даёт скачивать файлы больше 20 МБ. Уменьшите размер экспорта (отключите медиа или сократите период).»

## Приватность

- **Нет хранения в БД**  
  Бот не сохраняет результаты обработки в постоянное хранилище (БД и т.п.).

- **Файлы обрабатываются «на лету»**  
  Экспорт читается в памяти, нужная информация извлекается и отправляется пользователю в виде ответных сообщений/файлов.

- **Временные данные удаляются**  
  После завершения обработки временные файлы (если создаются) и состояния с информацией о загруженных файлах очищаются.

- **Нет прямого доступа к истории чата**  
  Бот не получает историю чата и список участников через Bot API, а работает только с файлами экспорта, которые ему вручную прислал пользователь.

## Запуск локально

1. Создать виртуальное окружение (по желанию) и установить зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Создать файл `.env` на основе `.env.example` и указать действительный `BOT_TOKEN` вашего бота.
3. Запустить бота:
   ```bash
   python -m bot.main
   ```

## Запуск через Docker

1. Создайте файл `.env` по образцу `.env.example` и укажите действительный `BOT_TOKEN`.
2. Соберите образ:
   ```bash
   docker build -t mephi-bot .
   ```
3. Запустите контейнер:
   ```bash
   docker run --rm --env-file .env mephi-bot
   ```
   Бот стартует и будет отвечать на команду `/start`.

## Запуск через docker-compose

Вместо ручного `build`/`run` можно использовать docker-compose:

```bash
docker compose up --build
```

Сервис `bot` возьмёт переменные из `.env` и будет перезапускаться автоматически.
